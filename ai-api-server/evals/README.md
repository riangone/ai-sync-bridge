# 検索品質の評価ゲート

`retrieval_gate.json` はブリッジの検索品質を測る 20 問のデータセットです。
`scripts/bench_bridge.py` は速度専用(検索語を本文から作るため精度は測れない)なので、
精度は必ずこのファイルで測ります。

## 実行

```bash
cd ai-api-server
.venv/bin/python scripts/eval_bridge.py \
    --profile ../demo-legacy-system/aisb_profile/bridge.yaml
```

出力は `recall@5` / `MRR` / 「回答不能語の棄却率」/ 「権限外漏洩件数」。
漏洩が 1 件でもあれば exit 1、recall が `--min-recall`(既定 0.8)未満でも exit 1 です。

## 測り方の決まり

- **検索語は文書の語をそのまま写さない。** 写すと BM25 が必ず勝ち、埋め込みの効果が見えません。
  20 問のうち 12 問は言い換え・要約形式(「取り消された受注」= Status:キャンセル 等)です。
- **`relevant: []` は「0 件を返すことが正解」** の質問です。カバレッジだけを上げる運用に
  すると、ノイズ文書が RAG の根拠に流れ込みます。`no_answer_rate` がその的中率です。
- **全問で ACL を検査**します。返った文書が 1 件でも閲覧不可ならテスト失敗です
  (検索 API は `retriever.search` を直接呼ぶので、経路の違いを含めて検証できます)。
- 期待文書は `source` / `entity` / `pk` で書きます。`who` は `retrieval_gate.json` 内の
  主体名(`sales_mgr` / `hr` など)で、実名・実 IP は使いません。

## 基準値(2026-11、ERP デモ、擬似埋め込み)

| 構成 | recall@5 | MRR | 回答不能語の棄却 | 漏洩 |
|---|---|---|---|---|
| 既定(ベクトル+BM25) | 0.340 | 0.292 | 1.00 | 0 |
| ベクトルのみ | 0.128 | 0.188 | 0.00 | 0 |
| BM25 のみ | 0.128 | 0.188 | 0.00 | 0 |

この数字が「いま売っている検索の実力」です。言い換え質問に弱いのは擬似埋め込み
(64 次元の文字ハッシュ)の性質で、実装の不具合ではありません。実埋め込みを入れたら
**この表の同じ行を測り直す**こと(下記)。

## 実モデルでの測り直し

```bash
GEMINI_API_KEY=... AISB_EVAL_ALLOW_REMOTE=1 \
.venv/bin/python scripts/eval_bridge.py --profile ../demo-legacy-system/aisb_profile/bridge.yaml \
    --embedder gemini
```

このスクリプトは対象データを Google の API へ送ります。顧客データを外部へ送れない
場合は、`--kb-dir` / `--kb-db` で合成データを使い、`AISB_EVAL_ALLOW_REMOTE` は
明示的に与えないでください(現行実装はこの環境変数が無いと実埋め込みでは動きません)。

## データセットの増やし方

1. 実際の質問や不的中を 1 問ずつ足す(期待文書と主体を必ず明記)。
2. 正解データが変わると基準値も変わるので、上の表を再生成する。
3. 40 問を超えたら、開発用(20)/保留用(残り)に分割して、開発用の調整で
   保留用を改善したかを確認する。
